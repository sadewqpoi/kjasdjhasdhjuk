# منصة مشجرة آل العلاط

منصة مشجرة عائلية تفاعلية فيها حسابات أعضاء، وربط موثّق بالأسماء الموجودة، وباقات واشتراكات، ودفع إلكتروني جاهز للربط، ولوحة إدارة كاملة.

## التشغيل

يحتاج Node.js 22.13 أو أحدث (قاعدة البيانات مدمجة `node:sqlite`، ولا يلزم تثبيت خادم قاعدة بيانات).

```bash
npm install
npm run import -- "E:\mjr\شجرة فرع سليمان العلاط.xlsx"
npm run create-admin -- 05XXXXXXXX "كلمة-مرور-قوية" "اسم المدير"
npm start
```

ثم افتح `http://localhost:3000`. شغّل الاختبار الشامل بالأمر `npm test` (28 حالة على قاعدة مؤقتة).

## البنية

```
src/
  db/schema.sql        مخطط قاعدة البيانات
  db/index.js          الاتصال + البيانات الأولية (المميزات والباقات الأربع)
  lib/subscriptions.js منطق الاشتراكات والصلاحيات (requireFeature)
  lib/payments/        طبقة الدفع: mock (للتطوير) و moyasar (مدى / Apple Pay / البطاقات)
  lib/otp.js           رموز التحقق من الجوال (console أو Unifonic)
  lib/tree.js          الأنساب والبحث بالاسم الثلاثي وحاسبة القرابة
  routes/              auth · link · tree · account · plans · payments · admin
public/                الواجهة (عربية RTL، بدون أي مكتبات خارجية)
scripts/               الاستيراد من Excel، إنشاء المدير، الاختبار الشامل
```

### الفصل بين البيانات
| الجدول | المحتوى |
|---|---|
| `persons` | السجل العائلي فقط (الاسم، الأب، الجنس، التواريخ). مستقل عن أي حساب. |
| `users` | حساب الدخول (الجوال، كلمة المرور، الصورة، الخصوصية). `person_id` عليه قيد **UNIQUE** يمنع ربط الشخص نفسه بأكثر من حساب، حتى على مستوى قاعدة البيانات. |
| `subscriptions` | اشتراكات المستخدم. يوجد فهرس فريد يسمح باشتراك فعّال واحد فقط لكل مستخدم. |
| `plans` / `features` / `plan_features` | الباقات ومميزاتها، وكلها قابلة للتعديل من لوحة الإدارة. |
| `payments` | سجل المدفوعات مع نتيجة التحقق من البوابة. |
| `link_requests` / `addition_requests` | طلبات ربط الحساب بالاسم وطلبات إضافة اسم جديد. |

### كيف تُطبَّق الصلاحيات فعليًا
كل مسار في الخادم محمي بـ `requireFeature('مفتاح')`، ويقرأ هذا المفتاح من باقة المستخدم في قاعدة البيانات عند كل طلب. لذلك إخفاء الأزرار في الواجهة ليس هو الحماية، بل هو تحسين للعرض فقط. الحقول الحساسة (التواريخ، الجوال، الصور) تُحذف من الاستجابة نفسها في الخادم. الصور لا توضع في مجلد عام، بل يقدّمها الخادم بعد فحص الباقة وإعدادات خصوصية صاحبها.

المميزات النظامية (يمكن تغيير اسمها وتوزيعها على الباقات من لوحة الإدارة):
`tree.view` · `tree.search` · `person.basic` · `person.photos` · `person.dates` · `tree.stats` · `tree.relationship` · `tree.export` · `person.contact` · `tree.certificate`

يمكن للمدير أيضًا إضافة مميزات مخصصة للعرض في صفحة الباقات. ربط ميزة جديدة بأداة فعلية يحتاج سطرًا واحدًا: `requireFeature('المفتاح')` على المسار الجديد.

### الرسائل الجماعية (دعوات وإعلانات)
لوحة الإدارة ← "الرسائل الجماعية" (صلاحية `announcements.send`): نوع الرسالة (دعوة، إعلان، تهنئة، تعزية، عامة)، عنوان ونص وصورة اختيارية، والمستلمون (كل الأعضاء الموثّقين أو المرتبطون بالمشجرة). تظهر فورًا في الموقع (بطاقة في الرئيسية، الإشعارات، صفحة "الدعوات والإعلانات")، وتُرسل على واتساب عبر طابور بطيء:
- **بوت واتساب** (QR، يدعم الصور): رسالة كل 5–9 ثوانٍ مع الحد اليومي `wa_bot_daily_limit`. يعمل إذا كان مفعّلًا كطريقة تحقق أو بخيار "استخدام بوت واتساب" في التبويب.
- **واتساب الرسمي**: يحتاج `wa_token` و`wa_phone_number_id` و**قالبًا معتمدًا** من Meta فيه متغير واحد `{{1}}` (اسمه ولغته يُضبطان من التبويب). نص فقط.
- إذا لم تكن هناك قناة جاهزة تبقى رسائل واتساب بالانتظار وتُرسل عند تجهيزها. يمكن إيقاف الإرسال أو إعادة محاولة ما تعذّر، ويرى المرسل من قرأها ومن وصلته.
- العضو يستطيع إيقاف استقبالها على واتساب من "حسابي" (تبقى في الموقع).

### إيقاف أقسام الموقع
لوحة الإدارة ← "الصفحة الرئيسية" ← "تشغيل وإيقاف أقسام الموقع": المناسبات، والاقتراحات والاستفسارات، ووصايا الأجداد. القسم الموقوف يختفي من الصفحة الرئيسية والقائمة والشريط السفلي والإشعارات، ويرفض الخادم طلبات الأعضاء له (`module_disabled`)، بينما تبقى إدارته متاحة.

### إيقاف ميزة لجميع الأعضاء
في "مصفوفة المميزات" يوجد زر تشغيل بجانب كل ميزة (مثل وثيقة النسب). إيقافه يمنع الميزة عن الجميع مهما كانت باقاتهم، حتى الإدارة، ويُخفي أزرارها ومربعها، ويرفض الخادم طلباتها (`feature_disabled`).

### وصايا الأجداد
من لوحة الإدارة ← "وصايا الأجداد" (صلاحية `wills.manage`): إضافة وصية بعنوان ونص، وصاحبها يُختار من المشجرة أو يُكتب اسمه، مع تاريخ ومصدر وصورة للوصية الأصلية (اختياري)، ونشر أو حفظ كمسودة، وترتيب. يقرؤها الأعضاء الموثّقون في صفحة "وصايا الأجداد"، ويظهر زر "وصيته" في بطاقة صاحبها داخل المشجرة.

### إيقاف الباقات والاشتراكات
من لوحة الإدارة ← "الباقات والمميزات" ← بطاقة "نظام الباقات والاشتراكات" يمكن إيقاف النظام كله بزر واحد. عند الإيقاف تُخفى صفحة الباقات ومربعها، ويرفض الخادم أي شراء أو تجديد أو إرسال تحويل، ويحصل الأعضاء إما على **كل المميزات مجانًا** أو على **مميزات الباقة المجانية فقط** (حسب الخيار). عند إعادة التشغيل يمكن تمديد الاشتراكات التي كانت سارية بنفس مدة الإيقاف. ويبقى إيقاف باقة واحدة (زر "إيقاف" بجانبها) أو اشتراك عضو واحد (تبويب الاشتراكات) متاحًا كما هو.

### الدفع
1. يرسل المتصفح رقم الباقة فقط، والخادم يأخذ المبلغ من قاعدة البيانات.
2. ينشئ الخادم سجل دفع بحالة `initiated` وفاتورة لدى البوابة.
3. عند عودة المستخدم أو وصول الـ Webhook، يستعلم الخادم من البوابة مباشرة بالمفتاح السري ويتحقق من: الحالة = paid، وتطابق المبلغ والعملة، وأن رقم سجل الدفع في بيانات الفاتورة هو نفسه.
4. بعدها فقط يُفعَّل الاشتراك داخل معاملة ذرّية. التحديث المشروط يمنع تفعيل الاشتراك مرتين إذا وصل الإشعار مرتين.

## الانتقال إلى الإنتاج

**الرفع على Hostinger (خادم VPS + دومين): اتبع الدليل خطوة بخطوة في [DEPLOY.md](DEPLOY.md)** — الرفع والتحديث بنقرة مزدوجة على `رفع-الموقع.cmd`. النقاط أدناه مرجع تفصيلي للإعدادات.

1. انسخ `.env.example` إلى `.env` واضبط `NODE_ENV=production` و`PUBLIC_URL=https://نطاقك`.
2. **بوابات الدفع تُدار من لوحة الإدارة ← "بوابات الدفع"** (للمدير العام): أضف بوابة من الأنواع المدعومة (ميسّر، تاب، PayTabs، تحويل بنكي يدوي)، واكتب مفاتيحها، وشغّلها أو أوقفها ورتّبها. يظهر لكل بوابة رابط Webhook خاص بها لتضعه في لوحة البوابة. مفاتيح ميسّر في `.env` تُستخدم مرة واحدة فقط لإنشاء أول بوابة. ملاحظة: تكامل تاب وPayTabs مكتوب وفق توثيقهما العام ولم يُجرَّب بحساب حقيقي، فجرّبهما بمفاتيح الاختبار أولًا.
   - **الطريقة القديمة عبر .env (ميسّر):** `PAYMENT_PROVIDER=moyasar`، ثم أضف `MOYASAR_SECRET_KEY`. في لوحة ميسّر أضف Webhook على `https://نطاقك/api/payments/webhook/moyasar` بنفس `MOYASAR_WEBHOOK_SECRET`. يمكن إضافة بوابة أخرى (HyperPay أو Tap) بملف جديد في `src/lib/payments/` فيه الدالتان `createCheckout` و`fetchStatus`.
3. **التحقق عبر واتساب (الافتراضي):** العضو يضغط زرًا يفتح واتساب برسالة جاهزة فيها رمز، ويرسلها من رقمه إلى رقم الصندوق. تصل الرسالة إلى الخادم عبر Webhook، فيتأكد من الرمز ومن أن المرسل هو نفس الرقم المسجل.
   - أنشئ تطبيقًا في [Meta for Developers](https://developers.facebook.com) وأضف منتج WhatsApp، وسجّل رقم الصندوق فيه (رقم غير مستخدم في تطبيق واتساب العادي).
   - في إعداد Webhook ضع الرابط `https://نطاقك/api/whatsapp/webhook` وكلمة التحقق نفسها التي في `WHATSAPP_VERIFY_TOKEN`، واشترك في حقل `messages`.
   - ضع في `.env`: `WHATSAPP_NUMBER` و`WHATSAPP_VERIFY_TOKEN` و`WHATSAPP_APP_SECRET`. واختياريًا `WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` ليصل للعضو رد "تم التفعيل".
   - بدون رقم مضبوط وفي وضع التطوير، تظهر في صفحة التحقق زر "محاكاة الإرسال" للتجربة.
   - **بوت واتساب الاحتياطي (غير رسمي):** من لوحة الإدارة ← الإعدادات ← "بوت واتساب": فعّله، ثم امسح رمز QR من جوال رقم البوت (واتساب ← الأجهزة المرتبطة). بعدها يظهر للأعضاء زر "أرسل لي الرمز على واتساب تلقائيًا" بجانب الطريقة الأساسية. بيانات الربط تُحفظ في `data/wa-bot-auth/` (لا تشاركها). **غير معتمد من واتساب وقد يُحظر الرقم؛ استخدم رقمًا منفصلًا.**
   - **الرسائل النصية (بديل):** `OTP_CHANNEL=sms` مع `SMS_PROVIDER=unifonic` مع `UNIFONIC_APP_SID` و`UNIFONIC_SENDER_ID`. في الإنتاج لا يُعاد رمز التحقق في الاستجابة أبدًا.
4. شغّل الموقع خلف HTTPS (مثل Nginx أو Caddy) حتى تعمل ملفات تعريف الارتباط الآمنة.
5. خذ نسخًا احتياطية دورية لمجلد `data/` (قاعدة البيانات والصور).
6. عند الحاجة إلى توسع كبير، يمكن نقل المخطط نفسه إلى PostgreSQL، لأن الاستعلامات مكتوبة بـ SQL قياسي ومجمّعة في طبقة واحدة.
